# יומן אימונים

אפליקציית ווב בקובץ אחד, בעברית, מימין לשמאל, מיועדת להתקנה למסך הבית של האייפון.
מודולים: אימונים שבועיים, מדידות וגדילה עם אחוזונים, וסטטיסטיקת משחקים.

הקבצים במאגר:

```
index.html        האפליקציה כולה. אין build, אין תלויות מקומיות.
firestore.rules   כללי הגישה לבסיס הנתונים.
firebase.json     הגדרות הפריסה.
.github/workflows/deploy.yml   פריסה אוטומטית בכל דחיפה ל main.
```

---

## מה משתנה כשמחברים חשבון

כל עוד בלוק ההגדרות בראש `index.html` ריק, האפליקציה עובדת בדיוק כמו קודם:
בלי חשבון, הנתונים נשמרים בדפדפן, והמעבר בין מכשירים נעשה בקובץ גיבוי.

ברגע שממלאים את ההגדרות, מתווספים שלושה דברים:

כניסת משתמש. הכניסה נדרשת לפני השימוש, עם Google או עם מייל וסיסמה.

ריבוי משתמשים. כל מי שנכנס מקבל מרחב נתונים משלו. השחקנים, האימונים,
המדידות והמשחקים שלו מבודדים לגמרי משאר המשתמשים, גם ברמת כללי הגישה
בשרת ולא רק בממשק. חבר של מיכאל שייכנס לאותה כתובת יראה יומן ריק משלו.

סנכרון. כל שינוי נשמר מקומית מיד ונשלח לשרת ברקע. כל רשומה נושאת חותמת זמן,
ולכן עריכה משני מכשירים במקביל לא מוחקת מידע: הגרסה המאוחרת מנצחת.
מחיקה מסומנת ולא נמחקת פיזית, כך שהיא לא חוזרת לחיים בסנכרון הבא.

---

## שיתוף מרחב בין שני אנשים

כדי שאדר ומיכאל יעבדו על אותם נתונים משני מכשירים, עם שני חשבונות נפרדים:

1. בעל המרחב פותח הגדרות ← חשבון וסנכרון, ומוסיף שם את המייל של השני.
2. הוא מוסר לו את קוד המרחב, שש אותיות וספרות שמופיעות באותו מסך.
3. השני נכנס לחשבון שלו, ובאותו מסך מזין את הקוד תחת מעבר למרחב אחר.

מהרגע הזה שניהם רואים ועורכים את אותם נתונים. הנתונים שהיו במכשיר של המצטרף
לפני המעבר מוחלפים בנתוני המרחב, ולכן כדאי לשמור גיבוי לפני המעבר אם יש בהם ערך.

הוספת מייל אפשרית רק לבעל המרחב. מי שהצטרף יכול לערוך נתונים, אבל לא לצרף אנשים נוספים.

## הקמת הפרויקט ב Firebase

### 1. פרויקט ובסיס נתונים

1. נכנסים ל `console.firebase.google.com` ופותחים פרויקט חדש.
2. Build ← Firestore Database ← Create database.
3. בוחרים production mode. האזור הקרוב ביותר הוא `me-west1` (תל אביב).

### 2. שיטות כניסה

Build ← Authentication ← Get started ← Sign-in method, ומפעילים:

```
Google
Email/Password
```

ב Google צריך לבחור כתובת מייל לתמיכה. זה שדה חובה.

### 3. כללי הגישה

Firestore Database ← Rules, מוחקים את מה שיש ומדביקים את תוכן `firestore.rules`
שבמאגר, ואז Publish.

כדאי לבדוק אותם במקום: באותו מסך יש Rules playground, שמאפשר לדמות קריאה
של משתמש אחד למרחב של משתמש אחר ולוודא שהיא נדחית.

### 4. העתקת ההגדרות לאפליקציה

Project settings ← General ← Your apps ← Web app (הסמל `</>`).
מקבלים בלוק כזה, ומעתיקים אותו אל ראש `index.html`:

```js
var FIREBASE_CONFIG = {
  apiKey: "...",
  authDomain: "PROJECT-ID.firebaseapp.com",
  projectId: "PROJECT-ID",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

המפתח הזה אינו סוד ולא צריך להסתיר אותו. הוא מזהה את הפרויקט בלבד.
מה שמגן על הנתונים הם כללי הגישה שבסעיף 3.

## איפה לארח את הקובץ

זו הנקודה היחידה שבה כדאי לסטות ממה שעשינו באפליקציית הוויות, ורק בגלל
הכניסה עם Google.

כניסה עם מייל וסיסמה היא קריאה ישירה לשרת ולא אכפת לה מהכתובת שבה הקובץ יושב.
כניסה עם Google חוזרת דרך כתובת עזר שיושבת תחת `authDomain`. כשכתובת האפליקציה
שונה מ `authDomain`, התהליך תלוי בגישה לאחסון חוצה־מקורות, וזו נחסמת כברירת מחדל
ב Safari מגרסה 16.1, ב Chrome מגרסה 115 וב Firefox מגרסה 109. בנוסף, בתוך אפליקציה
שהותקנה למסך הבית באייפון, חלון קופץ נפתח בהקשר שהאפליקציה לא יכולה להגיע אליו.
האפליקציה כאן כבר בוחרת בין חלון קופץ להפניה לפי מצב התצוגה, אבל זה לא פותר את
עניין הכתובת.

המסקנה המעשית: אם הקובץ יושב בכתובת `PROJECT-ID.firebaseapp.com`, כתובת האפליקציה
ו `authDomain` זהות, ושתי הבעיות נעלמות. זו הכתובת ש Firebase Hosting נותן בחינם.

### האפשרות המומלצת: המאגר ב GitHub, האירוח ב Firebase

הקוד ממשיך לשבת ב GitHub, והדחיפה ל main פורסת אותו אוטומטית.

פעם אחת, מהמחשב:

```bash
npm install -g firebase-tools
firebase login
firebase init hosting        # בוחרים את הפרויקט, ומציינים . כתיקיית הפרסום
firebase deploy --only hosting
```

לפריסה אוטומטית מ GitHub, מייצרים מפתח שירות:

```bash
firebase init hosting:github
```

הפקודה מחברת את המאגר ומוסיפה את הסוד `FIREBASE_SERVICE_ACCOUNT` בהגדרות שלו.
הקובץ `.github/workflows/deploy.yml` שבמאגר כבר מוכן לזה.

אחרי הפריסה פותחים באייפון, בסאפארי:

```
https://PROJECT-ID.firebaseapp.com
```

ואז שיתוף ← הוסף למסך הבית.

### אם בכל זאת GitHub Pages

עובד, בתנאי אחד: מוסיפים את `USERNAME.github.io` תחת
Authentication ← Settings ← Authorized domains.

Settings ← Pages ← Deploy from a branch ← main ← / (root), והכתובת תהיה
`https://USERNAME.github.io/REPO/`.

במסלול הזה כניסה עם מייל וסיסמה עובדת בכל מצב, וכניסה עם Google עובדת בדפדפן
רגיל אבל עלולה לא לחזור מתוך האפליקציה שהותקנה למסך הבית. אם זה קורה, נכנסים
פעם אחת עם מייל וסיסמה, או עוברים לאירוח שבסעיף הקודם.

הערה: GitHub Pages ממאגר פרטי דורש מנוי בתשלום. ממאגר ציבורי זה חינם, ואין בעיה
שהקוד יהיה ציבורי, כי הנתונים לא יושבים בו.

## גיבוי

הגיבוי לקובץ נשאר במקומו גם כשיש חשבון, והוא עדיין שימושי: הוא מוציא את כל
הנתונים החוצה בקובץ JSON אחד שאפשר לשמור בוואטסאפ או ב iCloud, ומאפשר לקרוא
אותם בלי תלות בשירות כלשהו.

התזכורת לשלוח גיבוי להורים אחרי הדוח השבועי מופיעה רק כשאין חשבון מחובר,
כי כשיש סנכרון הנתונים כבר לא יושבים על מכשיר אחד בלבד.

## עלות

הכל נכנס למסלול החינמי של Firebase, בפער גדול.
המסלול כולל חמישים אלף קריאות ועשרים אלף כתיבות ביום. שימוש רגיל של כמה ילדים
שמסמנים אימונים הוא עשרות פעולות ביום.
